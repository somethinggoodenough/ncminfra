## 1. 功能名称、编号和状态

F00 v1：建立最小正确性、完整生成性能基线和分阶段 profile 工具。下文保留提交审批时的方案；提交时尚未编写功能、测试或 benchmark 代码。

这是一个测量工作包：回答“当前代码到底算了什么、哪里耗时、后续改动如何被可靠验收”。本提案不以加速为交付目标；不把环境准备、测量或已有缺陷修复说成性能优化。

## 2. 具体用途和改前/改后场景

输入 WMT14 测试集中的一批德文句子，按 checkpoint 规则截断/补齐到 96 个 prompt tokens，执行固定 11 个 concept levels，生成 64 个位置的最终 token IDs，再按原规则处理 EOS/PAD、计算翻译指标。

现在，原入口能在满足依赖和权重条件时生成翻译、输出 BLEU，但没有可追溯的阶段时间、计时边界、独立窗口、forward 次数和显存记录。本机环境还不能运行该入口。

批准后，在隔离环境中保留相同模型、精度、长度、采样和输出行为，增加独立运行的 debug/benchmark 入口。交付每个阶段耗时、实际完成吞吐、峰值显存、原始样本记录和与冻结 upstream 的输出一致性结果。用户可据此决定 F01 或其他唯一下一项，而不凭猜测先写 kernel。

## 3. 问题与证据

固定源码证据见 [审计调用链](../audits/2026-10-23-kickoff.md)：

- `scripts/eval_shard.py:140–146` 的完整路径是 generate → latent 重建 → decoder → token selection，不能只测 Transformer。
- `models/next_concept.py:501–518` 在每个后续 level 重算 prompt；`:487–499` 的非零温度采样走排序/softmax/multinomial。它们是热点候选，当前占时未知。
- `models/next_concept.py:654,683` 的旧 KV mask 漏 padding bias，且 `:523` 拒绝 query_level0。旧 KV 仅能作缺陷诊断对象，不能作为质量合格的加速基线。
- `models/quant.py:635–668` 的历史 z_hats 有别名，F00 不用它们作独立 oracle。
- `evaluate.py`/`eval_merge.py` 没有此次要求的 manifest、唯一运行目录、五窗口统计协议。
- 本机实测仅包括环境：RTX 4060 8188 MiB；当前 Python 3.8.5、torch 1.12.1+cpu、无 SDPA/CUDA。20 个 Python 源文件的 AST 解析成功不等于模型测试成功。

**未测项**：所有模型输出、阶段耗时、任务质量、VRAM 峰值、harness 开销和 speedup。预期可建立测量能力，但不预设哪个算子占比最大。

## 4. 研究依据

[NCM 论文与官方代码](https://arxiv.org/abs/2610.14162v1) 定义 coarse-to-fine 与层内并行的对象；[PR #5](https://github.com/HazyResearch/ncm/pull/5) 提供已有 KV 修复和 benchmark 线索。本轮不合并该 PR，后续 F01 应先评估复用。其作者数字包含不同 commits/附加修复，不能作为当前本地基线。

[Denoising Surface](https://arxiv.org/abs/2610.00499v1) 提醒不能只用 NFE 表示异质步骤成本；本提案采用逐 level、逐 shape 成本记录，不训练该论文的预测器。[Mooncake](https://arxiv.org/abs/2407.00079v5)、[Sangam](https://arxiv.org/abs/2607.04206v1)、[BlockServe](https://arxiv.org/abs/2607.08930v1) 的调度思路留待有 profile 后再评估，本次没有 serving scheduler、通信或 SLO 实验。

这些来源支持测量方法和问题拆分，不提供本项目的收益保证。完整适用条件见研究核验报告。

## 5. 技术方案

### 执行顺序

1. 在 `worktrees/f00/` 建隔离实现分支，起点为固定 SHA；保留 `upstream/ncm/` 作为 clean reference。
2. 检查下载 metadata/剩余资源，在第 11 节限额内创建工作区专用 Python/CUDA 环境并锁定依赖；安装后先核验 import、SDPA、CUDA。
3. 完成最小 debug 与统计自检；获取唯一真实任务 WMT14 的指定文件，固定 remote revision、文件 SHA-256、输入序号与配置。
4. 用冻结 upstream 原入口生成 reference，完成输出/质量比对。只在正确性通过后做正式 B03；B01 profile 在另一次运行中执行。
5. 保存原始数据、结果报告和变更 commit，停止。任何独立 upstream bug 仅记录或提出新提案，不在 F00 内修复。

### 数据流、状态和调度单位

单进程、单 GPU、固定离线 batch；一个样本是一条完整生成请求，一次 batch 调用包含 B 个样本。同一请求的 levels 按原顺序执行，没有跨请求重排或连续 batching。

权重/codebook 生命周期为进程级；输入和输出带稳定 sample_id；codes、latent、RNG state 和计时记录由一次调用管理。reference 与被测路径用独立进程，加载相同 state dict。测试捕获的中间张量立即 detach/clone，计时路径不保留张量历史。生命周期结束后释放结果引用，保留原 GC 策略，不逐请求强制 collect/empty_cache。

不训练模型，不改 codebook、level schedule、context length、CFG 规则或采样算法。

### 观测方式

E2E 模式关闭阶段探针，仅在声明的入口/出口同步。profile/debug 模式通过可恢复的外部 method wrapper、module hook 和 `record_function` 标注现有函数；不改生产源码的运算。异常时 finally 撤销探针。

分阶段记录：输入 H2D、prompt embedding、level-0 stack/head/sample、每个后续 level 的 embedding/latent update/stack/head/sample、最终全部 codes 重建、decoder、token selection、输出 D2H。prompt 与 level-0 共用一次 stack 时分别标明其嵌套关系，不重复相加；每个后续 eager stack 包括重算 prompt 的成本。GPU profiler 若不可用，则用同一 stream 的 CUDA events 给出粗粒度阶段结果，明确不能获得逐 kernel 归因；不靠增加逐算子同步冒充正常性能。

## 7. 正确性约束

1. 保持完整 11-level WMT14 schedule、P=96、最终 64 个模型输出位置；PAD=151643，EOS 从同 revision tokenizer 读取。真实输入按 upstream 截断/右 padding，不改训练长度。
2. prompt 仅看有效 prompt；当前 target 看有效 prompt 和整个当前 level；禁止误用 causal target mask。空有效 prompt 在 harness 输入验证中拒绝，P=0 toy 不纳入支持范围；不暗改模型的空输入语义。
3. prompt 与每个 target level 的 RoPE 坐标分别从 0 重置；QK norm 在 RoPE 前；保持 level/head 索引映射。
4. 正式基线为 FP32 参数、无 autocast；torch runtime 默认 TF32/SDPA 策略必须在启动时读取并冻结记录。默认值本身不视为已知常量。
5. 另设 **R-math 数值诊断**：FP32、TF32 显式关闭、SDPA math；只作 oracle 比对，不把它当成较慢的性能对手。若为了数值复现切换测量精度/backend，需另列基线、更新提案，不混成系统收益。
6. 保持 WMT14 `temperature=1, top_k=1, top_p=0` 和 CFG 的 level-dependent 公式；CFG=0 与 1 分开报告。并列 top-k、RNG 消耗不优化。每个配对运行恢复 CPU/CUDA RNG 状态；固定种子 20261023、输入顺序和 batch 划分，跨 batch 的随机一致性不强求。
7. 全部 codes 参加最终重建。不能直接使用 generate 内未加入最后一层的临时 z_hat，不能以有别名的历史快照作 reference。
8. 同一个模型对象顺序调用；不支持并发、迁移、cache 共享。若运行旧 KV 缺陷用例，用独立对象/进程，不污染正式 eager 基线。

容差预先固定：独立 float64 dense attention/RoPE oracle 对 FP32 math 的元素比较为 `abs_err <= 1e-5 + 1e-4*abs(reference)`；小模型累计 latent/logits 为 `1e-4 + 1e-3*abs(reference)`。报告 max absolute/relative error，不只返回 allclose。mask 布尔可见性、位置索引、sample_id、codes 和最终 IDs 必须精确相等。相同模型/环境的 native CLI 与 harness 配对输出要求 100% 一致。非 FP32 不在本版容差范围内。

## 9. Benchmark tests（独立性能报告）

### 基线、硬件、workload

**U0**：未经修改的固定 upstream，在本次锁定环境上的 eager 路径。**H0**：F00 adapter 调用同一实现，profile 关闭。配对比较只用于识别 harness 开销，不叫模型加速。

U0 的测量 driver 只按 `eval_shard.run` 中原有计算顺序直接调用冻结模型类，并在同一边界完成 H2D/D2H；不把整个 evaluate 子进程的加载、detokenization 和评分耗时当 U0。该 driver 仍属于获批后的 F00 测量代码。正确性的独立对手则是原生 CLI 全流程，不能只让两个 adapter 互相对照。

已核验 KV 修复基线：**未建立 / NOT RUN**，待 F01 独立批准与质量通过。compile/graph 基线：**未建立 / NOT RUN**，本版无此策略。后续优化不得只对比 U0 而忽略已成立的更强 baseline。

硬件仅本机 RTX 4060 8GB；正式矩阵 WMT14 输入前 1024 个原始序号，B=1/4/8，各 CFG=0/1，共 6 个 cells。真实 prompt 长度分布、截断数与 PAD 比例写入 manifest；不合成额外长上下文。测量次序按固定 seed 打乱并保存，减少温度/背景负载偏差。若 B=8 或某 CFG OOM，按原 cell 报 BLOCKED，不偷偷替换成小 batch。

### 测量协议

| ID | 测量边界与流程 | 输出 |
| --- | --- | --- |
| B01 profile | 只在单独运行启用探针。覆盖上述 6 cells，每 cell 先稳定 warmup，再取 5 个独立窗口，每窗口 16 batches。阶段用 CUDA events/torch profiler，CPU 发射时间单列。`record_shapes` 等额外开销仅此模式。 | 各 level/阶段 GPU 时间、CPU 开销、实际 shapes、11 次 stack 调用、显存；嵌套区间标清，不能把阶段相加冒充无探针 E2E。profiler 不可用时报告粗粒度 events 范围。 |
| B03 E2E | 起点为 CPU 上已经 tokenized、padded 的本 batch IDs；计时前同步，然后开始 `perf_counter_ns`；包括 H2D、完整 generate、最终重建、decoder、token selection、D2H；最终 CPU IDs 就绪后同步/结束。排除文本 tokenization、detokenization、文件 I/O、加载和 scoring。 | 每 batch latency、samples/s、实际输出 tokens/s、allocated/reserved 峰值、各窗口原始记录。固定 batch 无在线排队，不叫在线服务延迟。 |

每个 U0/H0 cell 使用 **5 个独立测量窗口，每窗口完整 1024 个样本**。窗口用新进程初始化相同模型后 warmup，单独记录加载时间和实际 RNG。每个窗口前至少 warmup 10 batches；比较最近两个 5-batch 组的中位耗时，漂移 ≤5% 才开始；最多 50 batches，不稳定则报告失败，不无限预热。完整五窗口不能被单次长循环替代。

正式 B03 关闭 hook/profiler/逐算子同步。边界同步用于定义整次 batch 的 wall time；不声称测到未执行的多 stream/网络 overlap。冷启动、权重加载、第一次 CUDA 初始化和 warmup 单列；本版 compile/capture 均为 N/A。

正式每进程 1 个 generation worker；CPU intra-op/inter-op 线程数固定为 1，记录环境变量和实际取值；该部署选择在 U0/H0 一致。GC 默认启用且记录，不在计时内外每请求强制回收来隐藏 #4。峰值前 reset peak stats，并同时报基线 allocated/reserved 和峰值；不能把 allocator reserved 当活跃 tensor 泄漏。

吞吐分子只用成功完成样本；tokens/s 统计按原 EOS/PAD 策略实际输出的 token 数，并另列计算的固定 64 位置数，二者不混用。若发生失败/超时/OOM，记录分子分母、请求序号和异常，该 cell 不进入“有效性能比较”。本版不算 SLO goodput、不输出 p99 可靠性结论、不套 AR TPOT/ITL。

每 cell 汇总窗口中位数、IQR、min/max、窗口间 CV；U0/H0 以五组配对 ratio 报中位数并保留所有点。只有五窗口时置信区间会不稳定，不伪造高置信的尾延迟结论。

## 10. 成功与停止标准

- D01/D02/D03/D13 的 mandatory eager 项与 Q01 全部通过；已知 KV 缺陷独立报告，GPU 项无条件时写 BLOCKED，不能用 CPU 代替。
- B03 至少 B=1/4、CFG=0/1 的 U0/H0 cells 完成五窗口；B=8 是容量探索，OOM 可保留为有效的容量发现，但不得写成该 cell 性能完成。B01 对可运行 cells 完成上述五窗口，覆盖全生成阶段与调用数。
- 配对 H0 相对 U0 的中位额外耗时 ≤3%；超出则定位 adapter/计时开销，不能优化模型来补偿。小于噪声的差异只写“未观察到可靠差异”。
- 窗口间 CV ≤10% 才标记稳定性能基线；更高时允许一次有记录的环境诊断和完整五窗口重测，仍不稳则报告 NO_STABLE_MEASUREMENT。原始异常点保留。
- 到达下载/磁盘/GPU 时间预算，或 mandatory batch OOM、runtime 不兼容、模型/数据损坏、eager 正确性失败时停止并报告 BLOCKED/失败原因；不减少 levels、精度或样本掩盖失败。
- F00 预期 speedup 为 **不适用**；主要收益假设是可识别占时和避免错误 benchmark。没有测到可优化瓶颈也是有效结论。

## 12. 风险与失败处理

- Windows WDDM、桌面进程、温度会使时延波动；记录背景显存和窗口离散程度，稳定性门槛不满足则保留失败数据。
- 旧 OmegaConf 引用环可能影响长循环显存。保留 GC 行为，不能在 F00 偷合并 #4；若阻塞必要窗口，单列修复提案。
- 现有脚本有顶层执行副作用，不能直接 import 后假定没有加载/生成。reference 在独立进程运行原入口；harness 只复用模型类，adapter 与原入口输出做强比对。
- PR #13 的 snapshot 别名、#14 的评分风险会误导验证。F00 用独立累计 oracle、全新单 shard 输出目录和明确 3003 输入覆盖；发现真实评分不一致时停止，不能把两个同错的结果当正确。
- GPU kernel 的浮点差异可能影响近似并列决策；同环境 native/harness 不一致即调查，跨 backend R-math 的容差仅用于数值诊断，不代替真实输出门槛。
- checkpoint 和依赖精确大小未知；先 metadata 再有限额下载。下载/模型加载错误保留日志，不尝试无限重试或下载整个 collection。
- profile 增加开销，所有性能结论取探针关闭的 B03；无法细分某阶段时标 UNKNOWN，不能将残差随意归因。
- WMT14 的结论不能推广成 XSum、无条件生成或集群结论。F00 不承诺收益，不自动进入下一项。
