## 2. 当前完整调用链

```text
evaluate.py::main
  -> 每 GPU 启动 scripts/eval_shard.py
     -> 配置/权重/输入加载 -> prefix(item) 截断或右 padding
     -> run(x, l0)
        -> NextConceptTransformer.generate
           -> prompt embedding / 可选 context encoder
           -> level 0: query、predict 或外部提供 codes
           -> 对其余 levels 顺序循环
              codebook lookup -> 累计 latent -> 下一 level 输入
              Transformer + 当前 level head -> concept sampling
           -> 返回全部 levels 的 concept codes
        -> vq.idx_to_zhats(g)[1][-1] 完整重建最终 latent
        -> Decoder.forward -> pick_tokens -> 最终 token IDs
        -> CPU 列表、EOS/PAD 处理和 detokenization
     -> shard pickle
  -> scripts/eval_merge.py -> BLEU / ROUGE / Sudoku / generative PPL
```

### 状态所有权与生命周期

- 冻结权重、codebook、RoPE buffer 属于模型；VQ-VAE 通过 tuple 持有，不在 generator 的 module tree 中，必须单独管理设备和 eval 状态。
- prompt embedding、完整 codes 列表、z_hat 是单次 generate 的局部状态。z_hat 是原地更新，调试快照必须复制。
- 上游 `cached_k/cached_v/caching` 属于 attention module；每个 level 开始恢复到 prompt KV，再临时拼当前 level KV，finally 清空。它不是持续追加全部历史 level 的 AR cache。
- `_cfg` 也存放在 generator 对象，正常返回后清空；缓存加上该字段意味着同一对象不能直接并发调用并宣称请求隔离。异常路径的 `_cfg` 清理需在以后请求状态功能中审查。
- 当前用全局 PyTorch RNG，没有 request-local generator。F00 固定顺序和 RNG 状态；多请求调度前必须另行设计 RNG 所有权。
- prompt 的内部 attention 是双向；不同完整 prompt 即便有相同开头，也不能按 causal prefix 的规则精确共享。完整相同条件的 KV 复用才有可能成立。
